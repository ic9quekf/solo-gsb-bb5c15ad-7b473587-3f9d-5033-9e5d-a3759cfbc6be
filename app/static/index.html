1 · 目标配置

批量重放时，每个事件会分别签名并独立投递、重试到下面的全部目标； 仅当所有目标都成功，事件才标记为成功， 部分失败会保留各目标状态，可对失败事件仅重试失败目标。 每个目标使用自己的 URL、HMAC 密钥、重试次数与超时。

2 · 导入事件

支持单个 JSON 对象、数组，或 {"events":[...]}。 若对象含 event_id（或 id）则用作事件 ID，否则自动生成。 重复 ID 会覆盖旧载荷并重置状态。

5 · 实验数据快照备份 / 恢复

备份会把当前 settings / targets / events / deliveries / attempts 导出为 JSONL 压缩包（.zip）， 包内 manifest.json 记录每个文件的行数、字节数、SHA-256 与数据库版本。
恢复前会完整校验 manifest、SHA-256、固定字段顺序、事件载荷可解析性以及全部外键关系， 任一错误都拒绝写入；校验通过后在单事务内整体替换数据， 当前单目标配置始终保留，命名目标组随快照恢复（同时支持恢复旧版 v1 快照）。投递进行中无法恢复。
